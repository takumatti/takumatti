# 🐢 TortoiseGit 操作まとめ

現場で実際によく使う操作を、自分用メモとして整理。

---

## 🔄 フェッチ（Fetch）

### 目的
リモートの最新情報を取得する（マージはしない）

### 操作
右クリック → TortoiseGit → Fetch

### ポイント
- 他の人の更新状況を確認したいときに使う
- 自分のブランチは変更されない

---

## ⬇ プル（Pull）

### 目的
リモートの変更を取得し、現在のブランチに反映する

### 操作
右クリック → TortoiseGit → Pull

### ポイント
- 作業開始前は必ず実施
- フェッチ＋マージ（またはリベース）

---

## ✏ コミット（Commit）

### 目的
ローカルリポジトリに変更を記録する

### 操作
右クリック → Git Commit

### ポイント
- こまめにコミット
- 1コミット1目的を意識

---

## ⬆ プッシュ（Push）

### 目的
ローカルの変更をリモートに反映する

### 操作
右クリック → Git Push

### よくあるエラー

```
! [rejected]  main -> main (fetch first)
error: failed to push some refs
```

原因：
他の人の変更が先にリモートへ反映されている

---

## 🔀 マージ（Merge）

### 目的
別ブランチの変更を現在のブランチへ統合

### 操作
右クリック → Merge

### ポイント
- コンフリクトが発生する場合あり
- 共同開発ではよく使う

---

## 🔁 リベース（Rebase）

### 目的
自分のコミットを最新の履歴の上に付け直す

---

### 🔥 実体験ケース

1. プルを忘れて作業
2. コミット
3. プッシュ
4. エラー発生（先に他人がPushしていた）

---

### 解決方法（Rebaseを使用）

1. 右クリック → Pull
2. 「Rebase」を選択
3. コンフリクト解消
4. Push

### なぜRebaseを使う？

- 履歴が綺麗に一直線になる
- 不要なマージコミットが増えない

---

## 📦 スタッシュ（Stash）

### 目的
作業途中の変更を一時退避する

### 操作
右クリック → TortoiseGit → Stash Save

### 使用シーン

- 作業途中でブランチを切り替えたい
- 急ぎで別修正が必要になった

### 戻す方法

右クリック → Stash Pop

---

# 🧠 自分ルール

- 作業開始前は必ずPull
- Push前に差分確認
- コンフリクトは焦らず対応
- Rebaseは「履歴を綺麗にしたいとき」に使用

---

# 💡 学び

「Pullを忘れると事故る」

以後、作業開始前のPullを習慣化。
